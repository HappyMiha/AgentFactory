# Engine and AI planning advice

AF-GC-012 adds an explicit **Check PC and compare options** action in the local game-plan page. It calls the existing bounded Core011 hardware scan only after a click, then a read-only advice endpoint. No model, engine, installer, remote worker or payment is started.

The dated policy compares Godot Compatibility with local or cloud inference, preserves manual planning, and identifies Unity and Unreal as later qualification work. RAM, currently available memory, workspace free disk, reported OS, unknown VRAM, renderer verification and the Windows/Web target affect the explanation. Reports older than 15 minutes or from the future are not positive capacity evidence. The catalogue requires review by 6 October 2026.

The sources are the [Godot system requirements](https://docs.godotengine.org/en/stable/about/system_requirements.html) and [Ollama qwen2.5-coder:7b catalogue](https://ollama.com/library/qwen2.5-coder:7b), inspected on 6 September 2026. Approximate installed editor/templates and model download sizes are distinguished from project caches and inference memory. Time and monetary cost remain an explicitly unknown range until the selected hardware, network, provider tariff and real task are measured. No hourly speed, token price or game-completion promise is inferred.

The 8/4/10 GiB editor and 16/8/15 GiB local-model total-RAM/available-RAM/free-disk reserves are conservative **AgentFactory planning assumptions**, not upstream minimum requirements or measured admission limits. Known VRAM alone does not prove supported drivers or model acceleration. One local model is not an independent producer/reviewer pair. Cloud advice does not establish an eligible account or qualified hosted worker; a weak PC still needs a separately qualified editor host. Existing provider, age/access, budget and runtime admission gates remain authoritative.

Choosing an available option explicitly transfers only engine and an appended explanation into the unsaved form. Existing notes are retained; if the combined field exceeds its limit nothing is changed. The original source, genre, objective and deferred scope are preserved. Existing Core008 confirmation, immutable revision, stale-source and replay/conflict protections perform the separate save. Advice cannot silently shrink an ambitious idea. Its suggested small milestone is presented for review.

The API `POST /api/configuration-advice` accepts the current manual planning fields and a hardware report through the existing local authentication, write-scope/origin and tenant boundary. It bounds the body at 40 KB and reports a generic validation error without echoing private input. Hardware is client-reported planning input, never trusted qualification evidence. No records are created by comparison. The returned digest binds the input for diagnostics; it grants no execution authority. Browser responses and selection are invalidated when the form or displayed revision changes, and selection checks report freshness again.

Validation: decision tables cover constrained/medium hosts, unknown VRAM, stale reports/catalogue, unsupported OS and invalid observations. HTTP tests exercise access, bounded input and no revision creation. Chromium tests cover explicit selection/save, retained source/notes/ambition, delayed scan edits, oversized notes and scan failure/retry. Synthetic profiles qualify the decision policy only; actual model/renderer/game performance remains separate evidence.
