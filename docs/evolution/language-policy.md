# Мовна політика документації

[English](language-policy.en.md) · Українська

Рішення власника:2026-09-10. Редакція:LP1. Статус:погоджений підхід; повний англомовний портфель ще не підготовлений.

## Рішення

Lokvetia Core та Lokiravia розвиваються як міжнародні продукти з українською робочою мовою та повноцінною англійською документацією для зовнішнього оцінювання. Українські оригінали, дослідницькі висновки, архітектура й беклог зберігаються в Git. Англійська версія має дозволяти зрозуміти й оцінити проєкт без обов’язкового читання української.

Це один узгоджений портфель двома мовами. Переклад не створює окремих вимог, залежностей, пріоритетів або релізних обіцянок. Поточні canonical manifests і правила авторства Markdown/JSON не змінюються через це рішення.

## Публічний шлях читача

1. Англійський README з помітним переходом до української версії.
2. Повні англійські концепція, продуктова проблема, архітектура та межі відповідальності двох продуктів.
3. Узгоджені англійські порядок реалізації, перші релізи та критерії приймання.
4. Англійські детальні картки й дослідницькі аргументи, потрібні для перевірки ключових тверджень.
5. Окремий англомовний пакет для грантової заявки: проблема, новизна, дослідницькі питання, етапи, оцінювання результатів, ризики та обґрунтування ресурсів. Його адаптують до конкретного конкурсу; Git не замінює самодостатню заявку.

Історичні робочі нотатки перекладаються за потреби. Повнота шляху оцінювання важливіша за однакову кількість файлів кожною мовою. Українська версія лишається доступною для щоденного керування продуктами.

## Синхронність і якість

- Кожен переклад указує український оригінал та його точну редакцію або commit/hash. Зміна оригіналу потребує перевірки актуальності перекладу; застарілий переклад має видиму позначку.
- IDs, залежності, числа, статуси, обсяг релізу, критерії приймання й межі доказів однакові в обох мовах. Мовна редактура не змінює вимогу.
- Українська лишається мовою розробки концепції. Англійський текст проходить предметну та мовну перевірку; він має бути зрозумілим самостійно, без буквального перенесення неясних формулювань.
- Конфлікт між версіями вирішують через український оригінал і чинний canonical manifest; виправлення синхронізують. Окремого English runtime backlog не створюють.
- Автоматичну перевірку незмінних полів і позначення застарілості треба додати під час впровадження двомовності. Ця політика описує вимогу; готового translation checker або повного перекладу не заявлено.

## Збереження та межі поточної поставки

Уже підготовлені концепція, архітектура, джерельні висновки,280 вимог, порядок залежностей та склад перших релізів зберігаються у чинній документаційній гілці обох репозиторіїв. Ця поставка додає погоджену мовну політику українською й англійською; вона не оголошує весь портфель перекладеним або продукт реалізованим.

Наступний обсяг — повний англомовний шлях оцінювання в наведеній послідовності. Перенесення українських файлів не повинно ламати існуючі посилання. Анонімні літературні IDs, джерельні anchors і межі покриття зберігаються; назви книжок, самі книжки та приватні extraction caches не публікуються.
