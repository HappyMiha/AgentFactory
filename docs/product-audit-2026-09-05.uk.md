# Аудит AgentFactory для створення ігор користувачами 12+

Дата: **5 вересня 2026 року**. Базовий commit: `03bb23b8f58e64f1fc0e4a14ecb4ff1fe27ec32d`.

Ціль продукту: користувач описує гру, підключає доступні хмарні й локальні AI, отримує допомогу з налаштуванням ПК та середовища, а потім регулярно запускає готові версії гри й дає відгук.

План реалізації: [продуктовий backlog](game-creator-backlog.uk.md) та [машиночитаний backlog](../examples/game-creator-backlog.json). Цей документ описує стан на дату аудиту; наявність задачі в backlog не означає, що можливість уже реалізована.

## Висновок

**AgentFactory має основу для координації розробки, але поточний вебінтерфейс ще не забезпечує заявлений шлях створення гри для користувача 12+.** Панель показує завдання, виконання, провайдери, докази перевірок та рішення людини. Основний користувацький результат — створити, запустити та змінити власну гру — через цю панель не завершено.

Найважливіший наступний результат — один справжній наскрізний сценарій: **ідея → підключення → підготовка ПК → невелика гра Godot → Play → відгук → нова версія**. Позитивний результат simulation або agent review не замінює запуску гри.

«Майже будь-яка складність» — напрям розвитку, а не перевірювана обіцянка першого релізу. Спочатку потрібен підтверджений сценарій невеликої 2D-гри; підтримку Unity, складного 3D та мережевих ігор слід приймати окремими етапами.

## Межі та типи доказів

- **Код:** висновок із маршрутів API, статичного HTML/JS/CSS, документації або тестів. Це не свідчення успішного проходження в браузері.
- **Відтворено:** статус можна присвоїти тільки після виконаного сценарію із записом результату та умов.
- **Продуктова прогалина:** для цільового сценарію немає завершеного користувацького шляху; окремі нижчі компоненти можуть уже існувати.
- Перевірка не є дослідженням із дітьми. Зрозумілість для віку 12+ ще потрібно виміряти на цільовій аудиторії.
- Live-виклики платних AI, встановлення рушіїв і публікація ігор не вважаються перевіреними без окремих результатів виконання.

Браузерний запуск підтвердив відкриття операторської панелі та втрату чернетки під час refresh. Ізольовані backend-сценарії підтвердили результати AUD-04, AUD-10, AUD-15–18; вони не викликали платних провайдерів. Перевірка Confirm/Escape залишилася незавершеною: автоматичний контроль дозволів відхилив підтвердження зміни навіть у тимчасовому середовищі, діалог скасовано. Наявність тесту в репозиторії сама по собі не означає, що його виконано в цьому аудиті.

| Пакування та чистий wheel smoke | sdist/wheel зібрані; окреме venv поза checkout: `pip check`, CLI help і deterministic demo пройшли | Demo зупинився на human gate як очікується; це simulation, а не гра |
| GitHub CI базового commit | Unit jobs Linux/macOS впали; Windows jobs cancelled; wheel clean-install і Docker build пройшли | Це результати зовнішнього CI, а не повторений локальний Docker запуск |

Команди відтворення перевірки плану наведені у [беклозі](game-creator-backlog.uk.md#перевірка-й-імпорт). Локальні fixtures використовували окремі SQLite/Git робочі каталоги; користувацькі проєкти не змінювалися. Повні персональні environment paths, облікові дані та чутливі security reproduction details до репозиторію не додаються.

**Чому локальні тести зелені, а CI — ні:** у [CI run 33216099084](https://github.com/HappyMiha/AgentFactory/actions/runs/33216099084) перевірка subprocess cancellation викликає `tasklist.exe` на Linux/macOS, а monitor test очікує `ready` незалежно від наявності всіх provider CLI. На аудитованому Windows ПК потрібні executable були доступні, тож це не той самий стан, що чистий runner. Задача **AF-GC-001** повинна прибрати залежність тестів від персональної машини, не приховуючи провали. Два попередні run також мають failure, але їхні окремі причини тут не узагальнюються.

## Пріоритети

**P0** — блокує наскрізний результат першого продуктового релізу. **P1** — істотно погіршує надійність, зрозумілість або керованість. **P2** — покращує масштабування та зручність після основного сценарію. Пріоритет продуктової прогалини не є оцінкою вразливості.

## Знахідки

### AUD-01 · P0 · Немає завершеного шляху від ідеї до реальної гри

**Доказ: код і продуктова прогалина.** Навігація описує операторські сутності, а початок роботи пропонує завантаження специфікації або імпорт JSON. Кнопка запуску та модель API обмежені simulation.

Джерела: [`index.html:20`](../src/agent_factory/static/index.html#L20), [`index.html:68`](../src/agent_factory/static/index.html#L68), [`app.js:187`](../src/agent_factory/static/app.js#L187), [`app.js:246`](../src/agent_factory/static/app.js#L246), [`web.py:109`](../src/agent_factory/web.py#L109).

**Наслідок:** дитина не може почати з фрази «хочу гру про…» і завершити цей шлях запуском власної гри через поточний UI. Це висновок про вебсценарій, а не заперечення всіх CLI-можливостей.

**Приймання:** чистий профіль → ідея → короткий план → фактичний build → Play без JSON, task ID, командного рядка та ручного призначення внутрішніх ролей.

### AUD-02 · P1 · Скасування діалогу потребує перевірки після попереднього підтвердження

**Доказ: лише код; гіпотеза ще потребує браузерного відтворення.** `confirmCommand` повторно використовує dialog і читає `returnValue`, не скидаючи значення перед відкриттям. Слід перевірити, чи попереднє `confirm` не впливає на наступне закриття через Escape.

Джерело: [`app.js:220`](../src/agent_factory/static/app.js#L220). До відтворення це не слід описувати як підтверджене виконання небажаної команди.

**Приймання:** Confirm → новий діалог → Escape не надсилає запиту на зміну; Cancel, Escape та повторне відкриття перевірено для кожного типу команд. Якщо виконання після Escape підтвердиться, виправлення блокує реліз.

### AUD-03 · P1 · Автооновлення може стирати незбережені налаштування

**Доказ: відтворено в браузері.** У поле Model identity введено `audit-unsaved-model`; наступний refresh відновив серверне значення `anthropic:sonnet-5`. Картки агентів разом із полями model/provider повністю замінюються через `innerHTML`. Початковий інтервал — п’ять секунд.

Джерела: [`app.js:60`](../src/agent_factory/static/app.js#L60), [`app.js:337`](../src/agent_factory/static/app.js#L337), [`app.js:387`](../src/agent_factory/static/app.js#L387).

**Приймання:** чернетка, вибір провайдера, фокус і позиція курсора переживають щонайменше три оновлення; зміна даних на сервері не перезаписує активне редагування мовчки.

### AUD-04 · P1 · Завантаження простої ідеї не дає змістовного виконуваного плану

**Доказ: відтворено в ізольованому backend-сценарії та підтверджено кодом.** Абзац про Godot-гру з котом і трьома життями перетворився на epic із назви файлу; конкретні вимоги загубилися. UI обіцяє передати специфікацію агенту, але endpoint викликає детермінований парсер і повертає назву рекомендованого агента. Опис і критерії шаблонні; такий epic не має доступного запуску leaf task.

Джерела: [`index.html:68`](../src/agent_factory/static/index.html#L68), [`web.py:482`](../src/agent_factory/web.py#L482), [`backlog_analyzer.py:166`](../src/agent_factory/backlog_analyzer.py#L166), [`backlog_analyzer.py:182`](../src/agent_factory/backlog_analyzer.py#L182).

**Приймання:** звичайний український та англійський текст зберігається повністю; вимоги простежуються до вихідної ідеї; план має виконувані задачі й конкретні критерії. UI чесно позначає спосіб аналізу та дозволяє редагувати план до імпорту.

### AUD-05 · P0 · Початкове налаштування залишається роботою оператора

**Доказ: документація і продуктова прогалина.** Посібник вимагає Git, Python, Docker та автентифіковані provider CLI. Temporal, Worker і Local Control Center запускаються окремими командами. Покрокового майстра підключень у переглянутому UI немає.

Джерела: [`user-guide-uk.md:24`](user-guide-uk.md#L24), [`user-guide-uk.md:75`](user-guide-uk.md#L75), [`user-guide-uk.md:302`](user-guide-uk.md#L302), [`app.js:123`](../src/agent_factory/static/app.js#L123).

**Приймання:** майстер знаходить доступні інструменти, веде через підтримуваний login або захищене введення ключа, перевіряє підключення й пояснює відновлення після помилки. Система самостійно виконує погоджені підтримувані установки та зберігає їхній прогрес.

### AUD-06 · P1 · System monitor не дає рекомендацій за можливостями ПК

**Доказ: код і продуктова прогалина.** Monitor оцінює базу даних, міграції, провайдерів, агентів і виконання. У цій відповіді немає оцінки RAM, GPU/VRAM, вільного диску або сумісності локальної моделі та рушія.

Джерела: [`web.py:374`](../src/agent_factory/web.py#L374), [`environment.py:18`](../src/agent_factory/environment.py#L18), [`local_model_scheduler.py:49`](../src/agent_factory/local_model_scheduler.py#L49). Перевірка environment шукає executable; local model scheduler є контролем доступу до операцій через записи в БД, а не вимірюванням GPU або планувальником VRAM.

**Приймання:** користувач бачить виявлені характеристики, пояснення рекомендованих local/cloud варіантів, обсяг завантажень і достатність диску. Невідоме обладнання позначається як невідоме, а не отримує вигадану оцінку.

### AUD-07 · P0 · Немає продуктового контракту побудови й запуску гри

**Доказ: переглянуті UI/API та продуктова прогалина.** Run detail показує артефакти, verdicts, errors та керування Temporal. У ньому немає вибору перевіреної версії гри, Play або результату перевірки керування гравцем.

Джерела: [`app.js:196`](../src/agent_factory/static/app.js#L196), [`index.html:124`](../src/agent_factory/static/index.html#L124).

**Приймання:** перший engine adapter імпортує й будує справжній Godot-проєкт, перевіряє запуск, прив’язує build до версії вихідного коду та пропонує Play. Unity приймається окремою матрицею встановлення, створення проєкту, build і запуску.

### AUD-08 · P0 · Відгук користувача не замкнено в цикл версій гри

**Доказ: переглянутий UI та продуктова прогалина.** Доступні approval/reject для доказів, але немає сценарію «спробував гру → описав зміну → отримав наступну версію → повернув попередню».

Джерела: [`app.js:185`](../src/agent_factory/static/app.js#L185), [`app.js:323`](../src/agent_factory/static/app.js#L323), [`user-guide-uk.md:200`](user-guide-uk.md#L200).

**Приймання:** відгук прив’язується до конкретного build; запропонована зміна зрозуміла користувачу; нова версія проходить build/test; попередню перевірену версію можна запустити та відновити.

### AUD-09 · P1 · Повідомлення про готовність не ведуть до виправлення

**Доказ: код.** Monitor може позначити систему degraded через стан будь-якого провайдера; UI виводить технічні назви blockers із заміненими підкресленнями. Він не пояснює, чи потрібен цей провайдер обраному сценарію, і не дає дії для виправлення.

Джерела: [`web.py:391`](../src/agent_factory/web.py#L391), [`app.js:39`](../src/agent_factory/static/app.js#L39).

**Приймання:** готовність визначається для обраної гри й конфігурації; необраний провайдер не блокує підтримуваний сценарій. Кожна необхідна дія має коротке пояснення, кнопку виправлення та повторну перевірку.

### AUD-10 · P1 · Потрібне узгодження документації та авторизації API

**Доказ: відтворено в ізольованому backend-сценарії та підтверджено кодом; деталі безпеки не публікуються в цьому аудиті.** Виявлено розбіжність між загальним формулюванням посібника про захист mutation endpoints і фактичним покриттям маршрутів. Підтвердження наміру та автентифікація є різними властивостями системи.

Джерела: [`web.py`](../src/agent_factory/web.py), [`user-guide-uk.md:255`](user-guide-uk.md#L255), [політика повідомлення про безпеку](../SECURITY.md).

**Приймання:** є єдина задокументована модель доступу й централізована перевірка всіх відповідних маршрутів; автоматичні негативні перевірки підтверджують її покриття. Детальне security review проводиться відповідно до SECURITY.md.

### AUD-11 · P1 · Мова інтерфейсу й терміни не адаптовані до нового користувача

**Доказ: код.** UI англійський та оперує поняттями delivery contract, reviewer routing, lease і Founder. Фільтри очікують ручні значення status/type/priority та agent ID. Український посібник не локалізує сам інтерфейс.

Джерела: [`index.html:2`](../src/agent_factory/static/index.html#L2), [`index.html:20`](../src/agent_factory/static/index.html#L20), [`index.html:70`](../src/agent_factory/static/index.html#L70), [`app.js:187`](../src/agent_factory/static/app.js#L187).

**Приймання:** повні українська й англійська локалізації; основні дії названі мовою результату — «Моя гра», «Підключення», «Спробувати», «Змінити». Внутрішні діагностичні дані доступні в деталях; значення фільтрів обираються зі списків.

### AUD-12 · P1 · Accessibility baseline не покриває реальну динамічну поведінку

**Доказ: код тестів.** Наявні тести читають статичні HTML/CSS, шукають маркери та порівнюють дві задані пари кольорів. Вони не перевіряють динамічні картки, збереження фокусу, поведінку Escape або фактичний reflow. Мобільний CSS monitor містить незбалансовані дужки; вплив потрібно зафіксувати в браузері.

Джерела: [`test_accessibility.py:65`](../tests/test_accessibility.py#L65), [`styles.css:13`](../src/agent_factory/static/styles.css#L13), [manual checklist](accessibility-checklist.md).

**Приймання:** браузерні перевірки keyboard/focus/діалогів/редагування, 320 CSS px і 200% zoom; перевірка фактично відрендереного DOM; задокументований ручний screen-reader pass. Статичні перевірки залишаються швидким початковим рівнем.

### AUD-13 · P1 · Назва end-to-end тесту ширша за підтверджений результат

**Доказ: код тесту.** `test_control_center_e2e.py` використовує FastAPI TestClient та simulation. Він підтверджує ланцюжок UI-facing API, незалежні reviews і dry-run GitHub preview, але не запускає браузер, рушій чи гру.

Джерело: [`test_control_center_e2e.py:44`](../tests/test_control_center_e2e.py#L44).

**Приймання:** докази розділені на unit/API, browser, engine build та playable journey. Критерій «гра готова» потребує проходження останніх двох рівнів; результати пропущених перевірок позначаються явно.

### AUD-14 · P2 · Великі плани й результати потребують зручної навігації

**Доказ: код.** Список work items запитує до 200 записів, показує total, але не пропонує переходу до наступної сторінки. Частина доказів доступна через API/JSON-посилання, що потребує технічних знань.

Джерела: [`app.js:155`](../src/agent_factory/static/app.js#L155), [`app.js:108`](../src/agent_factory/static/app.js#L108).

**Приймання:** усі результати доступні через пошук і пагінацію; видно кількість показаних записів; користувач переглядає зміни та версії гри, а технічні докази відкриває за потреби.

### AUD-15 · P0 · Статус готового середовища випереджає фактичне налаштування

**Доказ: відтворено в ізольованому backend-сценарії.** `enter_development` послідовно змінює фази discovery/bootstrap/development, а Activity повертає `READY` і повідомлення про завершене налаштування. У перевіреному сценарії викликів `subprocess.run` і environment checks було нуль; тестовий репозиторій залишився незмінним, із самим README.

Джерела: [`coding_delivery.py:425`](../src/agent_factory/coding_delivery.py#L425), [`coding_delivery.py:485`](../src/agent_factory/coding_delivery.py#L485), [`activities.py:971`](../src/agent_factory/orchestration/temporal/activities.py#L971).

**Наслідок:** зміна фази є доказом роботи оркестрації, але не доказом установленого рушія, пакетів або працездатного тестового середовища. Висновок обмежений перевіреним шляхом bootstrap.

**Приймання:** `READY` потребує збережених результатів реальних probe/install/verify кроків для потрібних залежностей. Помилка або відсутній крок залишає зрозумілий blocked/failed стан; повторення є ідемпотентним.

### AUD-16 · P1 · Вибір моделі не гарантує фактичний запуск цієї моделі

**Доказ: відтворено в ізольованому тесті побудови запиту.** Для двох вибраних `agent.model` значень `local:model-a` та `local:model-b` CLIProvider утворив однакові аргументи й prompt. Стандартна конфігурація Ollama містить фіксовану модель `qwen2.5-coder:7b`. Це перевірка маршрутизації запиту, а не live inference.

Джерела: [`providers.py:401`](../src/agent_factory/providers.py#L401), [`providers.py:420`](../src/agent_factory/providers.py#L420), [`providers.json:131`](../src/agent_factory/defaults/providers.json#L131).

**Наслідок:** назва моделі в UI або reviewer record сама по собі не доводить, яка модель отримала роботу. Це також обмежує твердження про незалежність перевірки різними моделями.

**Приймання:** вибрана підтримувана модель явно відображається в фактичному запиті; результат зберігає requested та effective model identity. Непідтримувана заміна відхиляється; тести доводять відповідність запиту й відображених даних.

### AUD-17 · P0 · Стандартні provider roles не узгоджені з autonomous planning

**Доказ: відтворено до запуску subprocess.** П’ять role IDs planning pipeline та роль Developer не входять у стандартний allowlist Ollama. Планувальник передає ці role IDs, а provider відхиляє їх. Наявність локального CLI не доводить, що запланована автономна місія може початися.

Джерела: [`autonomous_planning_pipeline.py:122`](../src/agent_factory/autonomous_planning_pipeline.py#L122), [`providers.py:295`](../src/agent_factory/providers.py#L295), [`providers.json:135`](../src/agent_factory/defaults/providers.json#L135).

**Приймання:** до затвердження плану перевірена матриця role/capability/model; підтримувані planning/development маршрути реально кваліфіковані, заборонені ролі залишаються забороненими. Задача **AF-GC-042**. CLOUD planning окремо входить до **AF-GC-018**: чинна LOCAL-авторизація не повинна ставати прихованою залежністю хмарного M1 від локальної моделі.

### AUD-18 · P0 · Live child може втратити окремі ідентичності виконавця та reviewer

**Доказ: відтворено на функції прив’язки live execution, без виклику моделі.** Три stage templates з окремими code/review/policy models перетворилися на один child agent/role/model із загальної авторизації. Це не дозволяє вважати конфігураційні назви моделей доказом незалежного виконання.

Джерело: [`activities.py:1724`](../src/agent_factory/orchestration/temporal/activities.py#L1724).

**Приймання:** кожна stage зберігає scoped role та фактичну model identity; review виключає effective producer identity або явно чекає рішення людини. Задача **AF-GC-041** разом із **AF-GC-006**.

### Межа між worker-компонентами та продуктовим виконанням

У коді є `CodexCLIProcessDriver`, `ClaudeCodeProcessDriver`, managed worktrees і validators; вони мають тести. Однак штатний Temporal stage створює `AgentRuntime` і працює через текстові provider artifacts; у production source не знайдено конструкції цих writable drivers. Водночас завершення live child правильно вимагає інтегрованого Git commit. Це означає незавершене з’єднання компонентів, а не відсутність усіх worker primitives.

Джерела: [`activities.py:1873`](../src/agent_factory/orchestration/temporal/activities.py#L1873), [`coding_delivery.py:1166`](../src/agent_factory/coding_delivery.py#L1166), [`codex_worker.py`](../src/agent_factory/codex_worker.py), [`claude_worker.py`](../src/agent_factory/claude_worker.py). ## Рекомендований користувацький шлях

1. **Опиши гру.** Ідея звичайною мовою; короткі уточнення тільки там, де вони впливають на результат.
2. **Обери перший прототип.** Простий опис механіки, керування та того, що можна буде спробувати найраніше.
3. **Підключи AI.** Знайдені можливості, сценарій «ще нічого немає», login/key flow, перевірка підключення й зрозумілі межі витрат.
4. **Підготуй комп’ютер.** Перевірка обладнання, рекомендований рушій і модель, конкретний план установок, прогрес і відновлення.
5. **Стеж за створенням.** Людські назви етапів, останній перевірений результат, зрозумілі Pause/Stop/Resume та повідомлення про помилки.
6. **Спробуй і зміни.** Play для конкретної версії, відгук, наступна перевірена версія та повернення до попередньої.

## Вимірювані ворота релізу

Це запропоновані цілі приймання, а не вже виміряні показники.

- У дослідженні з цільовими користувачами щонайменше 80% учасників знаходять початок і завершують створення першого плану без підказки модератора за п’ять хвилин.
- На задокументованій підтримуваній конфігурації чисте встановлення проходить через UI; невірні облікові дані, відсутня мережа, недостатній диск і перезапуск мають перевірені сценарії відновлення.
- Перша Godot-гра містить керованого персонажа, зрозумілу ціль і завершення; справжні import/build/launch checks проходять до появи статусу «Можна грати».
- Запит на одну зміну після playtest утворює нову перевірену версію, зберігаючи можливість запустити попередню.
- У звіті релізу окремо наведено підтримувані ОС, рушії, провайдери, локальні моделі, фактичні витрати й результати перевірок; неперевірені комбінації не оголошуються підтримуваними.
